# v0.2 exit criteria: measured results

Measured on 2026-11-09 against the `feat/inboxes` tree that ships as 0.3.0, on a Mac mini (10 cores, 16 GB; the Docker VM had 6 CPUs and 8 GB). Each criterion has an automated test that passes; the numbers below are what those tests printed. The same flows were then run end to end against the real arm64 images (`drumsergio/ownhealth:0.3.0`, 363 MB unpacked, 84 MB to download; `drumsergio/ownhealth:0.3.0-ocr`, 436 MB unpacked, 109 MB to download) under `docker compose` with fresh volumes, a GreenMail mail server, a fake Paperless and a fake Nightscout. All data is synthetic: the Rivera family and the fictional LabNorte lab.

| Area | Criterion | Result | Test and number |
|---|---|---|---|
| Email | A password-protected lab PDF from an allowlisted sender appears in the review queue in <2 min; 100% of mail from other senders lands in quarantine | **Met** | `ownhealth-api` `inbox_email::a_locked_lab_report_from_an_allowed_sender_reaches_the_review_queue_in_under_two_minutes`: worst case 90.5 s (the 60 s poll, the 30 s scheduler tick, 0.5 s of work). `ownhealth-inbox` `email::every_message_not_allowed_is_quarantined_and_never_parsed`: 22 of 22 messages not allowed held, 0 parsed rows: 12 distinct cases (unknown, missing or doubled sender, forged, failing, missing or foreign authentication, an Authentication-Results from another server, lookalike domains) and 10 promotions with a PDF attached. ## Upgrade from 0.2.0

A 0.2.0 stack with an owner (password login), the LabNorte PDF imported and accepted (4 values) and a personal access token moved to the 0.3.0 image. The admin service applied migrations 1000, 1001 and 1050. The `state_hash` of the profile stayed `sha256:60ac6e7f…688d9a`, the token kept working over MCP, the session cookie stayed valid and the password login worked.

Repeated on the final tree after the inbox fixes, with the default image rebuilt (364 MB unpacked, 84 MB to download): a 0.2.0 stack with the demo family and a token moved to it, the admin service applied 1000, 1001 and 1050, all four profiles kept their `state_hash`, and the token still answered `get_health_status` over MCP with the same hash.
